# PDF Creator & Editor — v0.3.0

## 設計とデータ処理

React / TypeScript / Viteで日本語UIと履歴を管理し、PDF.jsで表示・座標・描画色を解析、pdf-lib + fontkitで編集・保存する。PDF.jsのWorker・CMap・標準フォント・WASM、日本語書体Noto Sans JP / Noto Serif JPは同梱する。AI、OCR、外部API、アクセス解析、ログイン、課金は使わない。PDF、パスワード、ファイル名、編集内容はサーバーへ送信しない。ファイルの入力・解析・編集・保存はブラウザ内で行い、原本ファイルを上書きしない。

- `src/pdf/reader.ts`：入力、ページ解析、回転座標、背景復元、編集データの再開とページ操作後の編集再対応。
- `appearance.ts` / `bounds.ts` / `background.ts` / `safety.ts`：元書式、字形範囲、単色背景、複雑な描画の判定。
- `output.ts`：書体選択、文字の配置・自動調整、背景と置換文字、保存。
- `operations.ts`：新規文書、文字・画像・図形追加、ページ操作、結合。
- `hidden-text.ts`：既に覆った元の文字をこのツールの選択候補から除外する非実行データ。PDF本体からの文字削除ではない。
- `project.ts`：原本バイト列と検証可能な編集データを専用ストリームで保存。
- `unlock.ts`：パスワード付きPDFから画像化した編集用コピーを作成。
- `src/components/`：画面部品。`App.tsx`：編集状態・履歴・画面遷移。

## 編集できる内容

文字をPDF上または一覧から選択し、内容、色、サイズ、太字、ゴシック・明朝・等幅、配置、位置を変更する。改行に対応する。選択単位はPDF.jsの文字列単位であり、必ずしも1文字・単語単位ではない。元フォント名・色・太さ・斜体を解析し、表現可能ならHelvetica / Times / Courier系列を利用する。その他は同梱NotoのRegular / Boldへ置換し、近似であることをUIに表示する。元の埋め込みフォントを抽出して再配布しない。日本語の字形欠落が再現したため、出力ではフォント全体を埋め込み、サブセット出力は使わない。

既定では元の範囲へ自動調整し、数字・金額は右端、一般文字列は左端を基準にする。幅が少し足りない場合は最大20%の横方向圧縮、それでも足りない場合はポイントサイズを下げる。罫線の近くでは文字の余白を縮め、実際の字形寸法を使って配置する。「元の領域に自動で収める」を外すと大きさ・位置を自由に指定できる。元書体・段落情報・複雑な文字間隔の完全再現は保証しない。

文字描画を除いた背景をPDF.jsで解析する（最大3倍・800万画素）。単色背景は同じ色のベクター矩形、画像・模様・罫線のある背景は変更する小さな範囲の画像として復元する。画像部分の拡大品質には解像度の限界がある。回転ページ・回転文字・UserUnitのあるページにも対応する。実際に重なる文字、縦書き、特殊なクリップ・透明マスク・混色等は自動置換を避ける。

自動選択で編集できない箇所や画像だけのスキャンPDFは「範囲書き換え」を使う。ドラッグまたは数値で範囲を指定し、選んだ色で覆って文字を配置する。範囲内の背景や罫線も覆うので、保存前のプレビュー確認が必要。「1文字ずつ縦に配置」は1文字ごとに改行する簡易配置で、日本語組版の縦書き処理ではない。自動選択できない文字から範囲書き換えへ移るボタンも用意する。完全に覆った元の文字は選択候補から除き、追加した文字を再編集できる。

白紙PDF、テキスト、PNG・JPEG・WebP・GIF・BMP画像、四角枠・線・半透明マーカー・塗りつぶしを追加できる。GIFは最初の画像、WebP・GIF・BMPはPNG化（最長辺4,096px）する。ページ追加・削除・前後移動・90度回転、PDF結合にも対応する。最後の1ページは削除しない。印刷は生成したPDFを別タブで開き、ChromeのPDF表示機能を利用する。

## 元に戻す・再編集・計算

文字変更に加えてページ・追加操作も同じ履歴で元に戻す・やり直す。履歴は最大40操作、文書バイト列の合計256 MBまで。このタブ内だけに保持する。文書変更後は元の文字・位置・ページ対応から既存編集と計算設定を再対応し、対応できない操作では文書を置き換えない。追加操作では現在の置換プレビューを原本として焼き付けず、既存の原本へ適用する。

この版で置換を保存したPDFには、原本と置換内容・計算設定を非実行の専用ストリームに含める。再読み込み時は原本を再解析して安全なIDへ結び直し、保存を繰り返しても原本や置換を入れ子に増やさない。編集データは16 MB・100,000件、原本は100 MBまで。圧縮ストリーム、不正な参照・計算設定は拒否する。隠した文字の選択除外情報も16 MB・100,000件までで、構造を検証する。原本を含むので出力ファイルは大きくなり、再読み込みの入力上限も受ける。外部アプリで後から加えた変更は、原本と編集データから再開すると反映されない場合がある。

合計の自動計算は同じページの明細金額と合計欄・税率を利用者が指定する。サンプルは150,000→160,000で、30,000と合わせて税込209,000へ更新。数量は乗算しない。税率0〜100%・小数第2位まで、税額は小計に対して一度計算して1円未満切捨て。円単位整数とBigIntを使い、負数・小数金額・不正な区切り・上限超過を拒否する。明細と合計は1操作で履歴・保存に記録する。計算対象を範囲書き換えで消した場合は設定を解除する。

## 実際の制約

ブラウザの資源保護として入力100 MB・2,000ページ、置換1件10,000文字、文字サイズ1〜720 pt。すべての文字領域を選択候補に表示するが、大きいPDFの処理時間・メモリ使用量には端末差がある。複雑な元PDFの完全な再現は保証しない。

パスワード付きPDFはパスワードをブラウザ内で使い、画像化したコピーとして開く（最大2.5倍・1ページ1,000万画素）。これは可逆な復号ではなく、文字情報・検索・リンク等は保持しない。範囲書き換えと追加機能で編集する。電子署名付きPDFも開けるが、編集・保存で署名は無効になる。

元の文字は覆う方式でPDF内に残る。選択除外のデータは機密情報の削除ではない。検索・コピー・専用データから元の情報を取得できる場合があるため、墨消しには使えない。画面に説明を残し、保存は常に別ファイルへダウンロードする。

## 実行

利用者向けには、サーバー起動不要の [HTMLファイル版](PORTABLE.md) も生成できる。以下は開発者向けの手順。

Node.js 24 を推奨。npm のキャッシュ先が書き込み禁止の環境では `npm --cache /tmp/pdf-creator-npm-cache ci` を使う。

```sh
npm ci
npm run dev
npm run test
npm run build
npm run preview
```

ブラウザの統合テスト（ビルド済みの本番用ファイルに対して実行）：

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

環境にインストール済みの Chromium を使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`。Windowsでは通常この環境変数は不要。公開・配信時は `dist/` のみを使用する。

Windows Chrome の現行安定版を主対象とする。オンボーディング環境では Linux Chromium で実機能を検証する。Windows 実機での確認は別途必要。

## 開発画面が表示されない場合

Viteを起動したまま `npm ci` を実行すると、開発サーバーが古い依存キャッシュを参照し、React等の読み込みで `504 / Outdated Optimize Dep` になることがある。依存関係を再インストールする前に、そのプロジェクトの開発サーバーを終了し、インストール完了後に再起動する。

すでに504が発生している場合は、その開発サーバーを終了してから次で依存キャッシュを再生成する。

```sh
npm run dev -- --port 5173 --strictPort --force
```

その後、画面を再読み込みする。編集内容はタブ内のメモリにしか保持されないため、操作可能なら先にPDFを保存する。起動確認はHTMLの取得だけでなく、画面表示とサンプルPDFの読み込み・変更・保存まで行う。本番ビルドのテスト成功だけでは、起動中の開発サーバーの正常性を確認できない。

## 今後の確認

Windows Chrome実機検証、任意PDFでの編集品質改善、大きい文書の負荷対策、表の新規作成、日本語縦書きの組版は引き続き課題。自動保存、バックエンド、認証、課金を追加する場合もローカル処理モジュールから分離する。


## v0.3.0 の精密編集

- ページ内の文字検索・候補の絞り込み・前後の候補移動、選択位置への移動、25〜800%表示。選択位置または表示中心を基準に拡大する。全ページ描画は引き続き1,200万画素まで。
- 選択範囲と周囲を4倍で元／適用後の2つのキャンバスへ切り出して比較。背景と文字をPDF.jsから直接描画し、主画面の縮小画像を拡大しない。切り出しは400万画素までで、大きい範囲は画素数を制限する。入力中の変更は適用後に反映する。
- 字幅10〜500%（0.1%入力）、行間0.5〜5倍（0.05倍入力）を元の置換と新規文字の両方で指定できる。プレビューと出力は同じ配置関数を使い、既定値100%／1.2倍は従来の出力を維持する。自動調整中は元の字形範囲へ収める処理を優先する。
- 位置の0.1pt微調整ボタン、矢印キー、Shift＋矢印の1pt移動。刻みは0.01〜10ptで指定可能。画面の矢印方向をページと文字の変換の逆行列で書字方向の移動量へ変換する。数値欄は元の文字の方向を基準にする。
- ユーザーが選んだ単体TTF・OTFをfontkitで解析し、既存文字と追加文字に適用。1ファイル20MB、合計50MB・16書体まで。OSのフォント一覧を収集せず、外部へ送らない。埋め込み禁止・画像専用・表示印刷のみで編集埋め込みが許可されないファイルはOS/2の実際の権限フラグに基づいて拒否する。その他の利用条件は利用者が確認する。太字・斜体を合成せず、入力ファイルの字形を使う。
- `custom-fonts.ts` が専用の非実行ストリームにフォントファイルを保存する。ID・件数・容量・参照・非圧縮条件を検証し、同じバイト列の再読込は重複登録しない。文書操作でも既存の同一ストリームを再利用し、フォントファイルを操作ごとに増やさない。再開時は保存したファイルを使用し、欠落時に黙って代替書体へ切り替えない。結合するPDFに保存されたフォントも引き継ぎ、IDが衝突するときは再割当する。フォント保存の容量上限を超える場合もページ表示は結合し、別途フォント選択が必要なことを表示する。字体の特殊な組版まで完全に一致する機能ではない。
- 保存する編集データのスキーマはv2。旧v1は引き続き読める。旧アプリが新しい字幅・行間・手元のフォントを無視して誤表示しないよう、古いアプリからのv2復元は拒否される。
- 通常の読み込み・自動置換が困難でもPDF.jsで表示できれば、画像化したコピーで編集を続けられる。現在のプレビューからの画像化は履歴の対象。文字・リンク等は失われ、最大2.5倍・1ページ1,000万画素の画像として保存する。破損して表示もできないPDFまで修復する機能ではない。

## v0.4.0 の複数ページ編集

- `search.ts` はPDF.jsの文字情報だけで全ページを順に検索し、背景の大きな画像を作らない。解析時と同じ非空文字のID・隠蔽済み文字の指紋を使用し、適用済み編集も検索する。キャンセル可能。文字領域単位のリテラル検索で、大文字小文字・全領域一致を指定できる。領域をまたぐ検索・OCR・正規表現は行わない。結果は100件ずつ表示するが、選択と置換は全結果を対象にできる。
- 一括置換は元の文字の書式・位置・自動調整を初期値にし、既存の手動書式設定がある場合は保持する。対象ごとに背景・描画・字形・収まりを検証し、除外理由を表示する。合計欄は直接置換せず、明細から再計算する。計算の失敗は全体を中止する。履歴への反映は一回で、undo/redoも一括となる。
- ページ複製は独立したページを作り、背景隠蔽の記録と適用済み文字編集を両方引き継ぐ。後続ページの編集IDも再割当する。自動計算の設定は既存ページに残し、複製側の計算結果は固定値として複製する（画面で説明）。ページは指定番号への移動にも対応する。
- `page-ranges.ts` は1始まりの範囲指定・逆順・重複を検証し、新しいPDFに選んだページをコピーする。適用済みのプレビューを出力し、隠蔽記録を新しいページ番号へ割当て、利用者フォントを保持する。元の順序に対応する復元プロジェクトは含めない。しおり・対話フォーム・文書全体の設定は引き継がない。機密情報の安全な削除機能ではない。
- `font-storage.ts` は埋め込みを完了後、FontDescriptorが参照する新規フォントプログラムだけを共有化する。圧縮バイト列・完全なストリーム辞書が一致するものをバイト比較し、参照をすべて転送してから新規の重複ストリームを削除する。既存ストリームを削除せず、CMap・文字コード・字形ID・幅は変更しない。同じ書体を繰り返し追加しても全文字のフォントプログラムを都度増やさない。非可逆圧縮や未検証の日本語サブセット化は行わない。
- 無料・AIなし・ブラウザ内処理を維持。追加依存なし。ブラウザのメモリ保護（100MB・2,000ページなど）は維持し、あらゆるPDFを完全再現できるという表示は行わない。

## v0.4.1 のクリック選択

文字枠を外れたクリックは8 CSS px以内で最も近い文字領域を選ぶ。倍率に応じた画面距離で判定し、同距離では小さい領域を優先する。選びやすさのために保存時の背景・置換範囲を拡大しない。座標は実際のページ要素のサイズから変換する。

選択できる文字情報がない場所をクリックすると、ページ内の小さな範囲を示して範囲書き換えへ移る。OCRは行わず、利用者が範囲を調整して新しい文字を入力・適用する。枠内の背景も覆うことを案内する。元のPDFはクリックだけでは変更せず、適用が必要。

上段の「文字を編集」を実際のボタンとし、画像追加・範囲書き換え等から文字の選択へ戻れるようにした。文字を選んだ後は、編集欄のマウントを待ってフォーカス・全選択・スクロールする。元の描画を安全に処理できない領域の制限と手動の書き換えは分けて維持する。

## v0.4.2 のブラウザ内請求書生成

作業環境内のファイルパスを利用者のダウンロードリンクとして渡さず、`#invoice=` のJSONデータからブラウザ内で請求書PDFを作成・表示し、既存の保存ボタンでダウンロードできる。宛先、請求元、項目、円の整数金額、請求日、期限を検証する。未指定の税率・銀行・登録番号などは生成しない。日本語フォントは検証済みの全体埋め込みを使用する。

請求書データはHTTPクエリに含めずURLフラグメントで受け取り、読込時にアドレスバーのフラグメントを取り除く。PDF・住所等をサーバーへ送信・公開・永続保存しない。フラグメントは暗号化ではなく文書データそのものなので、請求書リンクを共有すればその内容も共有される。データは最大8KB、文字200字/欄、金額は安全な整数、実在するISO日付・期限の前後関係を検証する。不正なリンクはエラーを表示し、通常のファイル読込は使用可能なままにする。
