# PDF Creator & Editor — Phase 1

## 設計

- React / TypeScript / Vite：日本語の編集画面と状態管理。
- PDF.js：ローカルの PDF 表示・テキスト座標抽出。Worker、CMap、標準フォント、WASM を同一オリジンから配信。
- pdf-lib + fontkit：元の PDF を保ったまま変更箇所を白い矩形で覆い、日本語フォントを埋め込んで文字を配置。
- Noto Sans JP：日本語の表示・出力。フォントは同梱し、外部フォント API は利用しない。
- PDF の内容、ファイル名、編集情報をサーバーに送信しない。解析・編集・出力はブラウザ内。永続保存、解析用ログ、AI、外部 API、アクセス解析は実装しない。
- `src/pdf/` は UI に依存しない読み込み・座標解析・出力処理、`src/components/` は表示、`App.tsx` は編集状態と画面遷移を担当。

## Phase 1 の範囲

ファイル読み込み、複数ページ表示、検出した文字列のクリック選択、白背景・横書き領域の置換、文字サイズ・色・左右中央の配置、幅・高さに合わせた縮小、日本語保存、ダウンロード、40操作までの元に戻す・やり直し。選択単位は PDF.js が検出した文字列で、必ずしも一文字や単語単位ではない。

元の書式を保つため、PDF.jsの描画命令から文字色を読み、フォント名と太字・斜体の情報を解析する。Helvetica／Times／Courierの標準書体は、その文字を表現できる場合に同じ書体を選ぶ。Arial等の近似や、同梱Noto Sans JP（Regular/Bold）への置換が必要な場合は編集欄に表示する。未知の日本語書体・文字間隔・日本語斜体などの完全な再現は保証しない。色が混在する文字列や透明・輪郭描画は、単一書式に潰さず編集を拒否する。

座標とベースラインを維持し、数字・金額は元の領域の右端、一般の文字列は左端を基準にする（実際の段落揃え情報を復元するものではない）。幅が少し足りない場合は横方向を最大20%圧縮し、それでも収まらない場合にポイントサイズを下げる。高さの制約も維持する。プレビューと保存で同じ書体選択・配置処理を使い、自動計算の合計欄にも元の色・書体を引き継ぐ。

「合計の自動計算」では、同じページの明細金額と合計欄を指定して連動できる。サンプル見積書は初期状態で明細2件・消費税10%を設定済み。150,000を160,000に変更すると、30,000と合わせた190,000に消費税19,000を加え、税込209,000へ更新する。数量は乗算せず、明細の金額欄を足す。税率は0〜100%・小数第2位まで、税額は小計に対して一度計算し1円未満を切り捨てる。円単位の整数とBigIntで計算し、負数・小数金額・不正な区切りや安全な上限を超える合計を拒否する。

明細と合計を1操作で履歴に記録するため、元に戻す・やり直すで同時に復元する。設定・解除も履歴の対象。合計欄は自動計算中に直接編集できない。計算設定はタブのメモリに保持し、PDFには計算結果を保存する。任意の見積書から計算式・税区分を自動推測する機能ではない。PDF内に残った変更前の数値を誤計算に使わないよう、保存済みの文字が重なるPDFではサンプル用の自動設定を行わない。

元の文字は白く覆うだけで PDF 内に残る。検索・コピーで元の文字を取得できるため、墨消し・機密情報の削除には使用できない。背景判定はレンダリング結果を使う保守的な推定であり、背景や複雑な図形の完全な保護を保証しない。保存前に画面の実際の PDF プレビューを確認する。

回転ページ、回転・縦書き文字、白以外の背景、文字同士が重なる領域は編集対象外。スキャン PDF は表示できるが OCR は行わない。パスワード付き PDF は Phase 1 対象外。署名済み PDF は編集すると署名が無効になるため使わないこと。フォント置換により元と字形・太さが異なる。改行を含む置換や、最低文字サイズでも収まらない入力は拒否する。

保存した PDF にも元の文字は残るため、再読み込み時の文字抽出に重複が生じ、再編集できない領域がある。編集履歴は開いているタブのメモリだけに保持される。元ファイルを別名で残し、同じタブで編集を完了する。

## 実行

利用者向けには、サーバー起動不要の [HTMLファイル版](PORTABLE.md) も生成できる。以下は開発者向けの手順。

Node.js 24 を推奨。npm のキャッシュ先が書き込み禁止の環境では `npm --cache /tmp/pdf-creator-npm-cache ci` を使う。

```sh
npm ci
npm run dev
npm run test
npm run build
npm run preview
```

ブラウザの統合テスト（ビルド済みの本番用ファイルに対して実行）：

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

環境にインストール済みの Chromium を使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`。Windowsでは通常この環境変数は不要。公開・配信時は `dist/` のみを使用する。

Windows Chrome の現行安定版を主対象とする。オンボーディング環境では Linux Chromium で実機能を検証する。Windows 実機での確認は別途必要。

## 開発画面が表示されない場合

Viteを起動したまま `npm ci` を実行すると、開発サーバーが古い依存キャッシュを参照し、React等の読み込みで `504 / Outdated Optimize Dep` になることがある。依存関係を再インストールする前に、そのプロジェクトの開発サーバーを終了し、インストール完了後に再起動する。

すでに504が発生している場合は、その開発サーバーを終了してから次で依存キャッシュを再生成する。

```sh
npm run dev -- --port 5173 --strictPort --force
```

その後、画面を再読み込みする。編集内容はタブ内のメモリにしか保持されないため、操作可能なら先にPDFを保存する。起動確認はHTMLの取得だけでなく、画面表示とサンプルPDFの読み込み・変更・保存まで行う。本番ビルドのテスト成功だけでは、起動中の開発サーバーの正常性を確認できない。
